## 2. 디자인 규칙 초안

브랜드(노란 포인트, 로고, 밝고 부드러운 분위기)는 유지하고 "정리"만 한다. 값은 `app/globals.css`의 `@theme` 토큰으로 한 곳에 둔다.

**색**
- `--color-primary` #FFDD57 (테마 값 유지): 배경·강조·아이콘용. **글자색으로 쓰지 않는다.**
- `--color-primary-ink` #7A5A00: 노란 계열 글자가 필요한 곳(링크, 첨부, 활성 텍스트). 흰 바탕 대비 6.5:1.
- `--color-on-primary` #1F2937: 노란 배경 위 글자(주 버튼, 활성 메뉴, 배지). 대비 10:1.
- `--color-secondary` #FFADCB (테마 값 유지): 배경 포인트만.
- 텍스트: 제목 #111827, 본문 #1F2937, 보조 #6B7280, 비활성 #9CA3AF.
- 배경: 페이지 #FAFAFA, 카드 #FFFFFF, 옅은 띠 `color-mix(primary 10%, white)`, 경계선 #E5E7EB.
- 파스텔 보조(홈 아이콘 카드에 이미 쓰는 초록·파랑·주황·보라): 배경 100단계 + 아이콘 500단계 한 쌍씩만 허용, 초록 하드코딩은 `primary` 파생으로 교체.
- 인사말 전용: `--color-greeting-text` #74675A, `--color-greeting-muted` #9A8C7E (현재 값 그대로 토큰화).

**글자**
- 폰트: Pretendard 단일(self-host 또는 preconnect), 이관 HTML의 font-family는 무시.
- 크기(PC / 모바일, 줄간격): h1 28/24 (1.3), h2 22/20 (1.35), h3 18 (1.45), 본문 16/16 (1.7), 작은 글 14 (1.5), 캡션 12 (1.4). 굵기 700/600/400.
- 페이지당 h1은 1개(페이지 제목). 상단 띠의 대분류명은 h1이 아니라 `<p>`/breadcrumb.
- 본문 읽기 폭 최대 720px, 페이지 컨테이너 1200px, 사이드바 260px.

**간격**
- 4px 기준. 섹션 간 64(PC)/40(모바일), 카드 안 24/16, 상단 띠 32/24, 목록 행 높이 56.
- 셸은 `min-h-screen`이 아니라 푸터를 화면 하단에 붙이는 flex 구조(빈 여백 제거).

**모서리·그림자**
- 카드 16px, 버튼·입력 10px, 배지 pill. 그림자는 카드 `shadow-sm` 한 종, hover에만 `shadow-md`.

**카드·버튼**
- 카드: 흰 배경, 1px #E5E7EB, 16px, 패딩 24/16, 제목 18/600.
- 버튼: primary = 노란 배경 + `on-primary` 글자, outline = 흰 배경 + 회색 테두리, ghost. 높이 40/44/52, 포커스 링 `primary-ink`.
- 배지 1종(pill, 12px, 배경 `primary` 20% + `primary-ink` 글자).

**본문(.content) 규칙** — 이관 HTML이든 새 글이든 같은 모습
- p 아래 여백 1em, 줄간격 1.7. h2 22px·h3 18px 위 여백 1.5em. ul/ol 기호 복원, 들여쓰기 1.25em.
- img: `max-width:100%; height:auto; display:block; margin:1.25em auto`, 이미지만 있는 문단은 여백 축소.
- table: `overflow-x:auto` 래퍼, 테두리 1px, 셀 패딩 8~12, 헤더 배경 옅은 노랑. 인라인 `width`는 max-width 100%로 제한.
- 이관 HTML 안전망: `.content [style]`의 font-family/font-size/color/line-height/letter-spacing 무시(inherit), `Skin_*`·`moduleConTitle`·`바탕글` 등 옛 class는 스타일 없음. pageMaker 조각(`.legacy-pagemaker img`)은 가운데 정렬, 폭 720px 제한, 조각 간 간격 0.

## 3. 수정 계획 (PR 단위, 승인 후 착수)

순서: A → B → D → C. 모든 PR은 `capture.mjs`로 프리뷰 URL을 같은 페이지 목록·같은 뷰포트로 캡처해 수정 전(운영)/후(프리뷰) 비교 이미지를 PR과 보고에 첨부.

**PR A. 디자인 기준 통일 (토큰 + 공통 컴포넌트)** — 문제 5·7·8·10·11·13·18
- `globals.css` `@theme`에 위 토큰 정의, 테마 주입(`lib/theme.ts`)이 primary/secondary 외에 배경·텍스트도 토큰으로 넘기도록 확장(프리셋 값 반영). 초록 하드코딩 제거.
- 공통 컴포넌트: `PageShell`(상단 띠 + 사이드바 + 본문 카드, CMS·정적·게시판이 같이 씀), `PageHeader`(h1 1개 + 부제), `ContentCard`, `EmptyState`(아이콘 + 문구), `Badge`, `Pagination`(aria 포함), Button primary 글자색 변경, 404 페이지(`app/not-found.tsx`).
- `<title>` 중복 제거, 푸터 셸 flex로 빈 여백 제거.
- 위험: 셸 교체는 모든 페이지에 닿으므로 인사말 렌더러는 그대로 두고 셸만 감싸는지 스크린샷으로 확인. 인사말 색은 토큰화만.
- 규모: 파일 15~20개, 2일.

**PR B. 본문 전용 스타일** — 문제 1(레이아웃 부분)·2·3(안전망)·15
- `@tailwindcss/typography` 설치 대신 자체 `.content` CSS(위 규칙) 작성. 모든 `prose` 래퍼를 `.content`로 교체(SinglePageRenderer, 공지·가정통신문 상세, 인사말은 자체 규칙 유지).
- 이미지 반응형·표 가로 스크롤·목록 기호·pageMaker 조각 정렬. 이관 인라인 스타일 무력화 안전망.
- 이관 `<img>`에 `loading="lazy"`·`decoding="async"` 부여(새니타이저 transform).
- pageMaker 흰 글자·빈 조각 문제는 CSS로 해결 불가 → PR E로 분리.
- 규모: 파일 6~8개, 1일.

**PR C. 이관 HTML 정리 (DB, dry-run → 백업 → 적용 → 롤백)** — 문제 3·6(일부)·14
- 대상: posts 68건(inline font/size/color/line-height/letter-spacing 제거, 중첩 span 평탄화, HWP class `바탕글`/`0` 제거, 빈 `<p> </p>`·연속 `<br>` 축약, 본문 첫 줄의 제목 중복 제거), pages 4건 richtext(`Skin_*`·`moduleConTitle` 등 class 제거, `Green_Table` → 일반 table, 굵게만 남긴 줄 정리), albums.description(빈 값 90건은 그대로).
- 표·이미지·링크·내용은 유지. `phase5-menu-align.ts`와 같은 방식의 `phase6-clean-html.ts`: 기본 dry-run(변경 행·전후 길이·제거 규칙 통계·샘플 diff 출력), `--apply`(전체 content 백업 JSON), `--rollback`.
- B의 안전망이 먼저 들어가야 정리 전후 화면 차이가 작음. 규모: 스크립트 1개 + 검증, 1일.

**PR D. 게시판 세부 + 모바일 메뉴** — 문제 4·9·12·16
- 게시판: 목록 날짜 컬럼 폭·모바일 레이아웃, 상세 제목 24px, 첨부 원본 파일명 표시(`legacy_meta.attachmentNames`) + 서버 경유 다운로드 또는 `?download=` 활용, 조회수 증가 복구 여부 결정, 앨범 상세 설명 문단 분리(줄바꿈 기준), 식단표 버튼, ListBoardRenderer → 공통 Pagination, 빈 상태 공통화.

**PR E (제안). pageMaker 페이지 16개 재구성** — 문제 1의 본질
- 원본 사이트의 정적 페이지는 로그인 없이 열리므로, 원본 페이지를 헤드리스 크롬으로 통짜 이미지(PC 폭)로 캡처해 페이지당 1장으로 교체하고 alt/본문 텍스트(OCR 또는 기존 이관 텍스트)를 함께 저장. 조각 나열·흰 글자·빈 조각 문제가 한 번에 사라지고 원본과 동일하게 보임. 모바일은 확대 보기 제공.
- 대안: 16개 페이지를 텍스트+표 HTML로 재작성(내용 재타이핑 필요, 가장 좋은 결과지만 수일 소요). 교원/반편성은 `/about/teachers`의 완성 이미지를 재사용하면 즉시 해결.
- 결정 필요: 통짜 이미지(빠름) vs 재작성(정석). 규모: 통짜 이미지 1일, 재작성 3~5일.
